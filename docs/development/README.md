# Разработка и квалификация NanoPi Zero2

Основной рабочий маршрут — [заводская FriendlyElec Ubuntu с SPI1](../guides/ubuntu-spi.md).
Результаты и конфигурации находятся в [справочнике проверок](../reference/validation/README.md).

## Сборочные варианты

- [Полный eFlasher-образ Ubuntu](ubuntu-image.md): сборка полного комплекта и его аппаратная установка не выполнены.
- [FriendlyElec Debian 13](friendlyelec-debian.md): проверены исходники и маршрут; аппаратная загрузка и вывод дисплея не выполнены.

## Незавершённые проверки

| Направление | Следующий проверяемый результат |
| --- | --- |
| XPT2046 на Ubuntu | Повторная девятиточечная калибровка, края, давление и отпускание; длительная работа одновременно с выводом ILI9341 |
| Установщик с `--touch` | Полный прогон на чистом образе, повторный запуск, дисплей и тач после перезагрузки |
| Восстановление | Отдельный прогон возврата бэкапа через recovery/microSD с сохранением версии и хеша |
| Armbian | Повторное сквозное развёртывание на точно указанном rolling-образе, квалификация CS1/IRQ/ads7846 и собственного overlay для тача |
| Armbian Ubuntu | Проверка libgpiod v2 в venv и полного маршрута дисплея на указанной версии |
| Права и автозапуск | Проверенные ограниченные udev-правила либо отдельный systemd service, без общего passwordless sudo |

## Доступ и автоматический запуск

Пользователь `pi` входит в группу `sudo`, но на обследованной системе
`sudo -n` не работает: требуется интерактивный пароль. Для ручного теста это
нормально.

Для production лучше запускать приложение как root через отдельный systemd
service либо создать ограниченные udev rules и группы для `gpiochip` и
`spidev`. Не выдавать пользователю общий passwordless sudo только ради
дисплея.

## Как оформлять результат

Для каждой процедуры фиксировать плату и периферию, образ ОС, kernel/SDK,
commit исходников, команды, входные и выходные хеши, наблюдаемый результат,
границы проверки и восстановление. Подготовленные команды, успешная сборка
и физический запуск — разные статусы.

После аппаратной проверки оформить руководство в `docs/guides/` и добавить
результат в `docs/reference/validation/`. Крупные образы, бэкапы и логи
сохранять вне Git; в документации оставлять компактное описание и хеши.
